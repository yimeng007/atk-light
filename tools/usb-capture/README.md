# USB 通信观察工具

用于查看 ATK 鼠标（`VID 0x373B`）的 USB HID 通信，辅助建立「设置项 ↔ 数据字段」的对应关系。

> 本目录只服务于**设备互操作性研究**：所有读写都通过设备公开的 HID 接口完成，
> 不涉及固件修改、不涉及任何加密绕过。工具仅用于观察与验证，不参与功能实现。

## 组件

| 文件 | 说明 |
| --- | --- |
| `USBPcapSetup-1.5.4.0.exe` | USBPcap 安装包（见上） |
| `capture.js` | 调用 `USBPcapCMD` 记录指定秒数的 USB 流量，存为 `.pcap` |
| `parse.js` | 从 `.pcap` 中提取 `reportId=8` 的 16 字节命令帧并按命令解码 |

## 用法

```bash
# 1. 记录 30 秒
node capture.js "\\.\USBPcap1" out.pcap 30

# 2. 看有哪些帧（原样列出）
node parse.js out.pcap

# 3. 按地址聚合，标出「值+补码」结构
node parse.js out.pcap --fields

# 4. 对比「改设置前 / 改设置后」两次抓包
node parse.js --diff before.pcap after.pcap
```

### `--fields` 输出示例

```
共 6 个地址，7 条读帧

0x0012  len=10  出现 1 次
  值(1次): 01 54 04 51 03 52 00 55 00 55
    结构: [0]+[1]=0x55  [2]+[3]=0x55  [4]+[5]=0x55  [6]+[7]=0x55  [8]+[9]=0x55
          ← 相邻和为常数，可能是「值+补码」
```

**「值+补码」是什么**：设备把参数存成 `[值][补码]` 两字节，补码 = `0x55 − 值`。
相邻两字节之和恒为 `0x55`，就说明这里是一对。**据此可以切出字段边界**，比盲扫快得多。

（脚本用贪心匹配，一个字节只属于一对，避免 `[1]+[2]` 这类因为下一个值恰好在旁边而产生的误报。）

### `--diff` 输出示例

```
对比：
  A(前) before.pcap  →  6 个地址
  B(后) after.pcap   →  6 个地址

0x0012  有 2 处变化
  [0]  0b → 0c    上下文 A: 0b 4a 07   B: 0c 49 07
       ↳ 该字节与相邻字节之和保持 0x55，符合「值+补码」结构

共 1 个地址发生变化。
```

**这就是「改一处、看哪里变」的自动化版本**：不用肉眼比对十六进制，
脚本会告诉你「哪些地址变了、变在第几个字节、上下文是什么、是不是值+补码对」。

### 典型的定位流程

1. 打开官方 HUB 的配置页，抓一次 → `before.pcap`
2. **只改一项设置**（例如 LOD 从 1.1 调到 1.3）
3. 再抓一次 → `after.pcap`
4. `node parse.js --diff before.pcap after.pcap`
5. 看哪些地址变了。**通常有 1-2 个"噪音"字段**（时间戳、计数），
   **再改一项、再抓一次、交叉对比**就能排除
6. 找到目标地址后，用 `--fields` 看它的完整值，推断编码规则
7. 写进自己的代码，**先只读不写**，确认读对了再尝试写

> ⚠ **写之前一定要先读原值备份**。写错地址可能把配置写坏，
> 而"恢复出厂"未必救得回来（不同型号的出厂值不一样）。

## 命令帧格式

16 字节定长帧，首字节为 `reportId=0x08`：

```
[08] [cmd] [addrLo] [addrHi] [len] [data ×10] [checksum]
```

- 校验：`checksum = 0x55 − (0x08 + cmd + addrLo + addrHi + len + Σdata) & 0xFF`
- 常用命令：`03` 在线查询、`04` 电量、`07` 写 EEPROM、`08` 读 EEPROM

## 分析方法（本项目实际用到的几条）

记录下来，免得下次重新摸一遍。

### 1. 先找「值 + 校验」成对的结构

ECC 校验让字段边界变得很好认：单个参数通常是 `[值][0x55−值]`，
索引类字段常带自己的 CRC。**相邻两个字节满足 `a + b == 0x55` 就能确认这是一对**。

例：`01 54`（档位 1）、`80 D5`（布尔开）、`06 4F`（LOD 6）。

### 2. 单次读取上限 10 字节

设备对 `len ≥ 12` 的读请求直接返回 `status=1`（无此项），看起来像"地址不存在"，
其实是**长度超限**。判断方法：同一地址用 `len=10` 能读、`len=12` 报错，就是长度问题。
必须按 10 字节分批读。

### 3. 用「改一处再看哪里变」定位字段

比盲扫地址可靠得多：先 dump 一片区域做基线，在界面里改一个设置，再 dump 同一片区域，
**只有真正对应的字段会变**。用这个方法确认了 LOD、灯效、按键映射、传感器修正的位置。

### 4. 区分「落盘」与「运行时」

同一个设置项可能只存在于 RAM，不写 EEPROM——超远距离模式就是这种：切换后 EEPROM 零变化，
重新连接自动复位。判断方法是**断电重连后再读一次**，值回默认的就不是持久设置。

### 5. 索引顺序不要想当然

物理位置（图上上下下）和 EEPROM 索引顺序不一定一致。本机实测侧键：
索引 `3` 对应**后退**、`4` 对应**前进**，与 HID 标准按钮位一致，但和界面上"前进在上"的直观顺序相反。
以实测为准。

## 关于蓝牙

当前设备只有**有线**与 **2.4G 接收器**两种连接方式，不涉及蓝牙。

另外，USBPcap 是 **USB 总线**嗅探工具，蓝牙走 HCI 协议栈、不在这条总线上，
即使设备支持蓝牙也无法用这套工具观察。蓝牙相关的分析方式暂时没有结论，等有设备再补。

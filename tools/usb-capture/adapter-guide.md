# 适配新设备 · 分步指南

面向想把本项目扩展到**别的型号**的人。这里不提供任何现成地址，
只提供一套「自己测出来」的流程——**连同每一步该问 AI 什么**。

> 前置条件：会开命令行、有一台 Windows、有一个能看代码的 AI 助手。
> 持续时间：熟悉的话半天到一天，第一次做可能两三天。

---

## 第 0 步 · 确认设备真的能被看到

**做什么**：先别急着抓包，确认设备在你的系统里暴露了可编程的 HID 通道。

用 Chrome / Edge 打开 `ATK-Light-网页版/index.html`，点「连接设备」，
看弹窗里有没有你的设备。

**看不到怎么办**：

- 有些设备需要先在官方驱动里启用"高级模式"
- 有些键盘/耳机根本不走 HID（纯音频、纯输入），**这类设备无法用本项目的方法**
- 接收器和本体可能是两个不同的 HID 设备，**两个都要试**

**可以问 AI**：

> 我用 WebHID 的 `navigator.hid.requestDevice()` 弹窗里看不到我的设备（品牌型号 XXX）。
> 设备管理器里它是"HID-compliant device"。可能是什么原因？怎么确认它有没有自定义 HID 通道？

---

## 第 1 步 · 抓一个"基准包"

**做什么**：不改任何设置，先抓一次，作为对照基线。

```bash
node tools/usb-capture/capture.js "\\.\USBPcap1" base.pcap 30
```

**抓包期间**：打开官方配置软件，**把配置页完整点一遍**（让软件把参数都读一遍）。
这一步很关键——如果软件不读，你就抓不到"配置快照"。

**验证抓到了什么**：

```bash
node tools/usb-capture/parse.js base.pcap --fields
```

**期望看到**：一串地址 + 每个地址的字节值。

**如果输出"没有读到配置帧"**：

- 官方软件没读配置（回到上面，把配置页点一遍）
- 或者这个设备用的是**另一条通道**（不是 16 字节帧）
- 或者 `parse.js` 的帧识别条件不匹配（帧头不是 `0x08`）

**可以问 AI**：

> 我用 parse.js --fields 分析抓包，输出"没有读到配置帧（cmd=8）"。
> 但官方软件确实能读到设置。可能是什么原因？我该怎么确认帧格式？

---

## 第 2 步 · 只改一项，再抓一次

**做什么**：**只改一项设置**，改完立刻再抓一次。

```bash
# 修改前先抓：base.pcap（第 1 步已做）
# 现在只改一项，例如把 LOD 从 1.1 调到 1.3
node tools/usb-capture/capture.js "\\.\USBPcap1" change1.pcap 30
```

**关键纪律**：

- **只改一项**。改两项就分不清是哪个引起的
- **改完马上抓**，别等
- **记住你改了什么、从多少改到多少**（后面推断编码要用）

---

## 第 3 步 · 对比，拿到候选地址

```bash
node tools/usb-capture/parse.js --diff base.pcap change1.pcap
```

**输出会告诉你**：哪些地址变了、变在第几个字节、上下文是什么。

**典型输出**：

```
0x0012  有 1 处变化
  [0]  0a → 0c    上下文 A: 0a 4b 07   B: 0c 49 07
       ↳ 该字节与相邻字节之和保持 0x55，符合「值+补码」结构
```

**这时候别急着下结论** —— 变化里通常混着噪音（时间戳、计数器）。

**可以问 AI**：

> 我改了 LOD 从 1.1 到 1.3，parse.js --diff 输出的变化地址是：
> 0x0012（[0] 0a→0c）、0x0034（[3] 12→13）、0x0056（[0] 时间戳变化）。
> 哪个最可能是 LOD？怎么验证？

---

## 第 4 步 · 交叉验证（**最关键的一步**）

**做什么**：**再改另一项**（比如把防抖从 4ms 改成 8ms），再抓一次，再 diff。

```bash
node tools/usb-capture/capture.js "\\.\USBPcap1" change2.pcap 30
node tools/usb-capture/parse.js --diff base.pcap change2.pcap
```

**原理**：

- 如果某个地址**两次都变**，它大概率不是目标字段（是噪音，比如时间戳）
- 如果某个地址**只在第一次变**，它很可能就是 LOD
- 如果某个地址**只在第二次变**，它很可能是防抖

**这一步能过滤掉 90% 的误判**，别跳过。

**可以问 AI**：

> 我第一次改 LOD，变的是 0x0012 和 0x0056；第二次改防抖，变的是 0x0034 和 0x0056。
> 0x0056 两次都变，是不是噪音？0x0012 和 0x0034 分别对应哪项？

---

## 第 5 步 · 推断编码规则

拿到地址后，还要搞清**值是怎么编码的**。

**做什么**：把同一项设置改成**多个不同的值**，每次都抓，看字节怎么变。

| 你设的值 | 读到的字节 | 推断 |
| --- | --- | --- |
| 1.1 mm | `0a` | — |
| 1.3 mm | `0c` | 涨 0.2mm → 字节 +2 |
| 1.5 mm | `0e` | 再涨 0.2mm → 再 +2 |

**结论**：`字节 = (mm - 0.7) / 0.1 + 1`，即每 0.1mm 对应 1。

**常见编码类型**：

- **线性**：值是 `a × 设定值 + b`（上面这种）
- **查表**：值不连续（如 `01 03 05 0a` 对应几档），需要逐个试
- **位掩码**：一个字节里塞了多个开关（如 `0b1010` 表示第 2、4 位开启）
- **组合**：高低位分开存（如 `[低字节][高字节]`）

**可以问 AI**：

> 我把 X 设置依次设为 1、2、3、5、10，读到的字节分别是 04、08、0c、14、28。
> 这像是线性编码吗？如果是，公式是什么？

---

## 第 6 步 · 写代码

**做什么**：把地址和编码规则写进 `index.html`。

参考现有的 `writeLod()` / `readLod()` 函数，**照葫芦画瓢**。

**改代码的纪律**：

1. **先只加读取**，不写
2. 读取成功后，在界面上显示出来，**和官方软件对一遍**
3. 确认读对了，再加写入
4. 写入函数**先复制现有的，再改地址和编码**

**可以问 AI**：

> 我要在 index.html 里加一个"传感器角度"的读写。现有 `writeLod` 是这样的：[贴代码]。
> 新字段在地址 0x0012，值是 `[x][crc][y][crc]` 四个字节。帮我照这个模式写。

---

## 第 7 步 · 只读验证（**必做**）

**做什么**：写完后**先只验证读取**，不碰写入。

**验证方法**：在官方软件里改一项，看你这边能不能读到新值。

**这一步能抓出 80% 的地址错误** —— 如果读出来的值和你设的对不上，地址肯定错了。

---

## 第 8 步 · 谨慎写入（**责任在这**）

**做什么**：确认读取无误后，才加写入。

**写入前必须做**：

1. **读原值并记录**（截图或复制到记事本）
2. 写入后**立刻回读校验**
3. 如果回读不对，**立刻写回原值**

**出事了怎么办**：

- 先用官方软件的「恢复出厂设置」试
- 不行就用抓包时的原值手动写回
- **还不行就只能送修** —— 这就是为什么"写之前先备份"是硬要求

**可以问 AI**：

> 我写入后回读，值不对（写 0x0c，读回来 0x0a）。可能是什么原因？
> 是地址错了、编码错了，还是需要同时写两个字节？

---

## 常见失败模式

| 现象 | 可能原因 | 怎么查 |
| --- | --- | --- |
| 弹窗里没有设备 | 没走自定义 HID / 需要官方驱动启用 | 设备管理器看有没有多出来的 HID 接口 |
| `--fields` 没输出 | 官方软件没读配置 / 帧格式不匹配 | 先抓一次"打开配置页"的包 |
| diff 出来一堆变化 | 有噪音字段 / 抓包期间设备在动 | 交叉验证（第 4 步） |
| 读出来的值和设置对不上 | 地址错了 / 编码理解错了 | 多试几个值（第 5 步） |
| 写进去没反应 | 长度不对（可能触发了单次读取上限）/ 地址只读 | 先读原值确认地址有效 |
| 写进去设备异常 | **地址错、写坏了** | 立刻写回原值 / 恢复出厂 |

---

## 一句话总结

**这个流程的核心不是"找到地址"，是"证明这个地址就是它"。**

单次 diff 出来的候选**永远不够**，必须用「改另一项、再抓、交叉对比」来排除。
这一步花的时间最值。

---

最后提醒：**本项目只对 ATK 设备做过实测**。适配其他品牌理论上可行，
但命令表、帧格式、校验方式可能完全不同，**等于从零开始**。
